B1 線上曲庫層 — 變更確認

一句話：把曲庫拆成「綁定核心 329 首（離線保底） + 線上擴充包（隨需下載、本地快取）」，從此加曲不用發新版。下面是會動到什麼、加上 4 個要你拍板的選擇。

難度 SML　🎯 = 我的建議

1 資料流（下載一首雲端曲）

① 使用者在曲目庫點一首「雲端」曲 (corpus:openscore/xxx)
↓
② 主程序 (Electron) 查 manifest 取得 URL + sha256
↓
③ 下載 .mxl → 驗 sha256 → 存 userData/corpus_cache/<id>.mxl
↓
④ 回傳本地檔路徑給 renderer → 引擎照常 parse(本地檔)
↓
⑤ 第二次點同一首 → 命中快取，離線也能開

2 會動到 / 不動的檔案

會新增 / 改動

  • 主程序：新 corpus-fetch.ts（抓 manifest、下載、驗 hash、快取、LRU 清理）+ 新 IPC corpus:resolve / listRemote / onProgress
  • preload.ts：暴露上述 IPC
  • renderer：曲目庫合併遠端 manifest、「雲端 / 需下載」徽章、下載進度 UI
  • host：上傳 catalog.json + 一批 .mxl

不動（重要）

  • 引擎 (Python)：保持離線、只讀檔 —— 不碰網路（安全邊界乾淨）
  • 既有 329 首綁定曲 + corpus: 解析照舊
  • 既有匯入 / 改編 / 播放流程

3 要你拍板的 4 個選擇

D1 — host 放哪？

manifest + .mxl 檔案的存放與下載來源。

D2 — 誰負責下載？

關係到安全邊界。

D3 — 本地快取上限？

下載過的曲存在 userData/corpus_cache，超過上限用 LRU 淘汰。

D4 — manifest 跟 .mxl 放一起還是分離？
