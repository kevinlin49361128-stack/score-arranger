三、路線 C 的工作項 (多選 — 🎯 已預勾建議範圍)

P0MC1 · 統一節拍器 model (修 #4)🎯

獨立節拍器與播放內點擊共用同一份設定 (音色/重音/細分/音量/訓練器) 與同一個 click engine 抽象。改一處兩邊一致，不再各走各的。

P1LC2 · Practice Session model (Mic/分手/熱圖/指法/loop/trainer/count-in 同一 state)🎯

一個正式 PracticeSession 結構承接目前散落的練習狀態，各面板讀寫同一份，不再各自 localStorage/local state。也是 #6 的務實起點。

P1MC3 · 每曲保存 metronome / practice / rehearsal 設定🎯

跟著曲子/tab 存：BPM、拍號、重音、count-in、loop 範圍、trainer、分手模式、rehearsal notes。下次開同一首自動恢復。#6 的可落地切片。

P1MC4 · 練習流程串接 (loop + speed trainer + count-in + practice log 一條龍)🎯

選段→count-in→loop+漸進加速→自動把這段練習結果 (速度/次數/達標) 寫進 practice log。把這幾版各自的零件接成一個流程。

P2LC5 · 完整老師↔學生工作流

老師指派曲目/段落/目標速度 → 學生練習 (自動記錄) → 回報進度 → 老師看 dashboard。把既有 TeacherHub/StudentCard/practice log 串成閉環。較大、可後續。

建議首發範圍 (🎯 已預勾)

0.1.65 sprint：P0 兩項 (architecture.md + refine 安全) + C1 統一節拍器 + C3 每曲保存設定。先把「我剛造的分裂」收掉並讓設定不流失 —— 立即有感、風險小。

0.1.66 sprint：C2 Practice Session model + C4 練習流程串接。把散落狀態收進一個 model，是 C5 的地基。

反方/取捨：C2 的 PracticeSession model 是這條路線的核心投資，做不好會變成「又一層抽象」。建議 C1/C3 先上 (小、獨立)，用它們的需求反推 C2 的最小 schema，不要先設計大 model 再硬塞。
