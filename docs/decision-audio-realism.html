Score Arranger · 2026-06-10 · 勾選要投資的路線（可複選），底部可複製決策摘要
背景：0.1.114 修復了物理建模無聲（worklet CSP），音色迭代到「鋸齒+梳狀+琴體 formant」。 本次 session 的教訓：(1) VSCO 直接啟用因錄音電平不一致而爆平衡；(2) 純合成弓弦難逼真； (3) 沒有客觀 QA 迴圈時，音訊回歸只能靠 Kevin 耳朵抓 → 來回成本高。
產品定位提醒：播放是「改編預覽」，使用者最終給真人演奏 —— 播放只需「清楚、平衡、有表現力」，不需逼真到取代錄音。

前置（無論選哪條路線都建議先做）

工時 ~1 session風險 低價值 讓所有音訊工作可驗證

把這次「只聽到大提琴」這種回歸變成 CI 可抓：

  • 平衡測試：離線 render 各樂器 C 大調音階 → 量有效 LUFS，斷言落在鋼琴參考 ±2dB 內。換取樣/調 fader 跑一次就知道有沒有爆。
  • A/B bounce：重用既有 OfflineContext 匯出（#32），一鍵把音色變體 render 成 WAV 檔 → Kevin 一分鐘聽 5 個版本，不用裝 app 來回。

＋ 直接解掉本 session 最大的痛（盲迭代）；所有後續路線的地基。

路線選項

工時 ~2-3 sessions風險 低-中真實感提升 ★★★★

VSCO-2 失敗的不是音質，是沒做電平校正就上線。正確做法是離線預處理管線：

  • 下載 VSCO-2 CE（CC0，可自由改製散布）→ 逐音符 LUFS 響度正規化 → 轉檔瘦身 → 自架（重用既有 corpus_cache 懶下載模式，不肥大 app）。
  • 多 articulation 切換（sustain / pizz / staccato / tremolo）+ 2 力度層 crossfade —— 引擎已經知道弓法和 articulation（A1/B3 已做），只差播放端接線。
  • 音色座位感：每件樂器 EQ + 定位 + early reflection（現有 A4 panner 延伸）。

＋ 業界共識：取樣的「真實感÷工時」無可匹敵；90% 的聽感提升來自這裡。

－ 工程多於演算法（管線、manifest、快取）；VSCO CE 錄音品質中上、非頂級。

工時 ~2-4 sessions風險 中真實感提升 ★★★★（在 A 之上疊加）

「假」的最大來源常不是音色而是演奏呆板。NotePerformer 的核心是讀譜的 AI 表現力，而本專案已經有樂句偵測、和聲分析、弓法生成 —— 譜面智慧是現成資產，缺的只是把它接到播放排程：

  • 樂句級力度造型（起句漸入、句尾收束、和聲張力 → 強弱）。
  • Agogics 微時值（句首微遲、終止式微緩）— 量很小就很有效。
  • 圓滑線真連奏（音尾搭接 + bow change 雜訊）、長音內 crescendo（雙力度層 crossfade）。

＋ 利用本專案獨有的分析引擎，是別人難抄的差異化；純控制邏輯，無新 DSP 風險。

－ 「好聽的表現力」要靠耳驗迭代調參（QA harness 的 A/B bounce 因此重要）。

工時 time-box 1-2 sessions風險 高真實感提升 ★★（上限明確）

若要續投 C1，兩個真正有效的升級（不是再調參數）：

  • 琴體改 convolution：用實測小提琴琴身 impulse response（或從真實取樣反推頻譜包絡）取代 parametric formant —— 木質感的差距主要在這。Tone.Convolver 現成。
  • 弓弦改真波導：Faust pm.lib 有現成 bowed-string 模型，faust2wasm 可直接編成 AudioWorklet（CSP 已修通，這條路現在才可行）。

⚠ 誠實的上限：SWAM 級的擬真需要連續控制器輸入（弓壓/弓速曲線）+ 多年調校；純譜面驅動的 PM 天花板就是「有趣的合成弦樂」。建議 time-box，到期用耳朵投票 keep/kill。

＋ 無授權問題、體積零、長音內動態天生連續；教學上「聽得到弓的物理」有獨特價值。

－ 投報率最低的一條；有沉沒成本陷阱。

工時 ~2-3 sessions (PoC)風險 高真實感提升 ★★★★?（未驗證）

2026 的新選項：DDSP 系列（Apache-2，模型僅數 MB）能從音符+表現力參數合成相當逼真的小提琴/大提琴。定位成「匯出擬真音訊 demo」功能而非即時播放：

  • 走 homr 模式 —— Python 端可選引擎、按需下載，不肥大主程式、不碰即時路徑。
  • 引擎已有完整 IR + 表現力資料 → 餵 MIDI-DDSP 的 note→expression→audio 管線剛好對口。
  • 給教師的賣點：「改編完，一鍵生成可以放給學生聽的示範音檔」。

－ 品質未驗證（音準漂移、複音=逐聲部跑模型）；增加 Python 依賴面；先 PoC 聽過再決定。

工時 0風險 機會成本而已

反方選項，認真列出：播放只是預覽，nbrosowsky + A 路表現力「夠用」。OMR/homr 還在收尾、Epic C 拆檔、教師工作流都在排隊 —— 音色的邊際價值可能低於這些。

⚠ 若選此項，建議仍做前置 P（QA harness 很便宜，且防止未來音訊回歸）。

建議的執行順序（若全採納）

P（QA harness）→ A（取樣地基）→ B（表現力）→ C/D 擇一 time-box 試水
理由：P 讓之後每步可驗證；A 是聽感提升的大頭；B 疊在 A 上且用到獨有的分析引擎； C 與 D 都是實驗性，等 A+B 落地後用 A/B bounce 直接比，數據說話再決定續投或砍。
