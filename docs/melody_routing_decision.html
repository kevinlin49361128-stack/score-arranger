主旋律聲部分配控制 — 方向決策

「改編時讓使用者選主旋律落在哪個聲部 / 在聲部間遊走」可行性分析 + 範圍規劃

結論：技術上可行，而且地基大半已經在了。 現有資料模型 Assignment(source→target, span, function=MELODY) 就是「這段主旋律 → 哪個聲部、哪幾小節」的表示； 引擎也已經會自動把主旋律逐樂句在聲部間遊走（_apply_melody_handoff）並在主手/副手間分擔。 缺的主要是 ①使用者控制權（一個能覆寫自動選擇的輸入/UI）＋ ②兩個全新能力：加倍(1→N) 與 跨音域移調(降到中提/大提)。

① 現況：引擎已經做了什麼

主旋律 → 目標聲部的自動決策

✓ 已有 — pick_target_for_function(MELODY,…)：自動挑「音域上界最高 + 技能最高」的聲部（弦四 → Violin I）。

就是這個預設決定了主旋律落在誰身上。要做的「讓使用者選」＝ 給它一個覆寫輸入。

主旋律逐樂句在聲部間遊走

✓ 已有 — _apply_melody_handoff + _melody_handoff_spans：縮編時（來源聲部 > 目標）主旋律已會逐樂句跟著來源換手，且嚴守「同一樂句不換聲部，只在樂句邊界換」。

但目前是跟著原曲來源走，不是使用者指定。Kevin 要的「指定遊走」＝ 讓人改寫這些逐樂句指派。

主手 / 副手分擔（Violin I ↔ Violin II）

✓ 已有 — _find_secondary_melody_target：找同family、技能較低的副手，把容易的樂句分給它。主旋律已能在 V1/V2 間流動。

逐聲部重新分配 + 鎖定

✓ 已有 — 譜面拖拉 reassign、is_user_edited/is_phrase_locked、修復尊重鎖定。改寫指派的「編輯+保護」管線已在。

② Kevin 的四個訴求 → 難度與缺口

A. 指定主旋律聲部（同音域）地基已在

缺：覆寫輸入 + UI

讓主旋律在 Violin I / II / Viola 間選一個落點（音域放得下、不需移調）。資料模型與 build 流程都已支援，只差一個 melody_routing 參數餵進 arrange + 一個選擇 UI。

反方：Viola 接小提琴旋律時高音域可能吃力（高把位）→ 需靠既有 difficulty/range 檢查提示。

B. 主旋律加倍（Violin I + II 齊奏/八度）新能力・中

缺：1 來源 → N 目標的「加倍」概念

目前一個 Assignment = 1 源 → 1 標。加倍要支援 1 源 → 2 標（齊奏或 8va）。演奏性容易（兩把同線）。

反方：加倍會稀釋和聲 — Violin II 去陪旋律，原本的內聲部就空了。是取捨不是免費。

D. 四聲部逐句遊走（指定路線）地基已在・中

缺：讓使用者「指定」每句落點的 UI

引擎已會 handoff 遊走；這裡是把「自動跟來源」變成「使用者排程」(句1→V1, 句2→Viola, 句3→Cello…)。Assignment.span 逐句表示已支援，缺前端排程 + 餵進 arrange。每換一個旋律承擔者，其餘三聲部要重填和聲（function 分配已能處理）。

反方：引擎做得到，但好不好聽是音樂判斷 — 旋律每句亂跳會突兀。應是「使用者驅動工具」，不是自動預設。

C. 降八度 / 降Key 移到中提・大提較難・需重配器

缺：移調落位 + 和聲重平衡

小提琴旋律（G4–E6）放不進大提琴舒適音域，必須降 1–2 個八度才放得下 → 本質上是重新配器，不是單純搬移：女高音線變成男高音/低音線，音樂色彩整個變。且大提原本的低音角色要讓位給誰、和聲要不要整層上移，都要處理。

需釐清：你說的「降Key」是整曲變調（全域 transpose，已有）還是只把旋律降八度搬到低聲部（八度位移）？兩者差很多。

③ 範圍決策（請挑一個）

選項 1 — 只做 A（指定聲部 MVP）

A：主旋律落點可選（同音域，逐段/逐句），不含加倍/移調
最小可行：一個 melody_routing 參數 + 選擇 UI。最快看到「我能決定旋律在誰身上」。
工程量：小（~1 個 sprint）。風險：低。覆蓋 Kevin 訴求：約 40%。
🎯 建議

選項 2 — A + B + D（路由 + 加倍 + 指定遊走）

同音域的完整控制：選聲部、加倍齊奏、四聲部逐句排程遊走 —— 不含跨音域降調(C)
用已有的 handoff/assignment 地基，交付 Kevin 大部分願景（旋律在 V1、V1+II、四聲部間遊走），且全是同音域或單純八度移動，不碰高風險的和聲重配器。C（降到中低聲部）獨立成 v2，等這套 UX 驗證後再做。
工程量：中（~2–3 sprint）。風險：中低。覆蓋：約 75%。建議理由：價值/風險比最好。

選項 3 — 全做 A+B+C+D（含跨音域移調）

完整願景，含把旋律降八度/降Key 搬到中提・大提 + 自動重平衡和聲
最完整，但 C 需要做「移調落位 + 和聲整層重配 + 重跑可演奏性」，是音樂與工程都最重的一塊。
工程量：大（~4–5 sprint）。風險：中高（重配器易出「聽起來怪」）。覆蓋：100%。

⑤ 落地路徑（建議的 A+B+D）

  • 引擎：arrange 收 melody_routing（每段/句 → 目標 player(s)）；覆寫 pick_target_for_function 與 handoff 的自動選擇；加倍 = MELODY assignment 容許多目標（齊奏/8va）。
  • 資料模型：Assignment 幾乎不用動（已有 span/function/target）；加倍可加 double_target_player_id 或讓多個 MELODY assignment 共用同 span。
  • UI：在改編設定 / 指派面板加「主旋律路線」編輯器 —— 一條時間軸（逐段/句）× 聲部選擇 + 加倍開關；沿用既有拖拉 reassign 的視覺。
  • 驗證：每次路由改動重跑可演奏性 + difficulty（高把位、跨弦會被既有檢查抓到）。
  • C(v2) 另排：移調落位 + 和聲重配，獨立 sprint，配 A/B 比較聽感。
